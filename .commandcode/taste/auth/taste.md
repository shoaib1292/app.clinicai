# auth
- 2FA must be optional: only enforce 2FA during login if the user has already enabled it in their settings; never block login for users who haven't set up 2FA. Confidence: 0.85
- Google OAuth sign-in must never reject an unknown email with an error — always provide a path forward. For patient-context sign-ins (from booking link), auto-create the patient record directly since Google provides enough data (name, email). For staff-context sign-ins (from `/login`), however, Google only provides name/email — which is insufficient for clinic creation (clinic name, city, WhatsApp number, etc. are required). New staff users must be redirected to the signup page with pre-filled email/name so they complete the full registration form before getting an account. Confidence: 0.85
- Email verification is mandatory for new clinic signups — if the user did not sign up via Google, they must verify their email (via Brevo-sent verification code/link) before onboarding begins. Unverified accounts cannot proceed past signup. The user explicitly restated this requirement: "jo bhi new emails aayen gi unka verification lazmi hai". Confidence: 0.90
- When mandatory email verification would block pre-existing accounts during testing, backfill them as verified (mark `emailVerified`) so the user can test immediately — verification enforcement applies to NEW signups only, not retroactively to already-existing accounts. The user asked "jo already hai... verify kr do ta k test kr sakon". Confidence: 0.70
- When a clinic admin adds staff (doctor, receptionist, lab technician, etc.), the system must send an invitation email via Brevo with a password-setup link. The invitation token must have a generous expiry (long enough that staff who don't check email immediately can still onboard). Confidence: 0.80
- Email-based account linking: if a staff member (doctor, receptionist, etc.) was invited via email and later signs in with Google using that same email, they must be resolved to their existing staff account — not create a duplicate or a new clinic. The email address is the unifying identity across auth methods. Confidence: 0.85
