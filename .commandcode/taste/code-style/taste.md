# code-style
- In Next.js 16 (Webpack), avoid `dynamic(() => ..., { ssr: false })` in Server Components — it's disallowed. Use direct static imports for `'use client'` components instead; the client boundary already handles SSR opt-out. Confidence: 0.80
- Keep computationally simple/deterministic logic (word count, delay formulas, scoring) as pure rule-based functions — never add LLM calls for calculations that can be done with basic math. Confidence: 0.80
- Remove ZAI/Z.AI integration code entirely and use OpenAI as the sole LLM provider — do not keep ZAI as a fallback or disabled option. Confidence: 0.90
- When passing data from a Next.js server component to a client component, never spread full Prisma/decorated objects (`...record`) — explicitly pick only serializable primitive fields. Prisma internals like `_count`, Date objects, and binary fields leak across the server-client boundary and cause serialization errors. Confidence: 0.80
- Remove unused npm dependencies immediately when discovered — dead deps bloat node_modules and slow install/build times. Verify with grep before removing. Confidence: 0.75
- When a feature is labeled "AI" (AI Wizard, AI Generated, etc.), it must call a real LLM — never use string interpolation or template substitution disguised as AI. Fake AI makes features feel disappointing and erodes user trust. Confidence: 0.75
- When the same UI pattern is implemented in multiple places (local component + separate shared component + similar-but-different variants like KpiPill), consolidate into a single canonical shared component with props for variation, then replace all scattered usages. The cleanup must be thorough: remove now-dead local function definitions, strip unused imports (motion, AnimatedCounter, etc.), and simplify prop/config data structures that carried fields only the old local component needed (color, trend strings). Confidence: 0.75
- Use CSS variables for all design tokens in UI components — `--primary`, `--secondary`, `--radius`, `--font`, `--shadow`, and semantic tokens like `--website-bg`, `--website-text`, `--website-surface`, `--website-border`. Never hardcode Tailwind color/text utility classes (e.g., `bg-white`, `text-black`, `bg-gray-100`); always reference CSS variables instead (`bg-[var(--website-bg)]`, `text-[var(--website-text)]`). Tailwind layout utilities (flex, grid, gap, padding) are still fine. This keeps theming and rebranding changes scoped to variable definitions rather than scattered across dozens of component files. Confidence: 0.85
- In Next.js Server Components, never use inline DOM event handlers (`onMouseEnter`, `onMouseLeave`, `onClick`, etc.) — they cause "Event handlers cannot be passed to Client Component props" errors. Use CSS-only alternatives instead: Tailwind `group-hover:` / `hover:` / `focus:` utilities for visual effects, and only convert to a `'use client'` component when JavaScript-driven interactivity is truly necessary. Confidence: 0.75
- When removing the last usage of an imported symbol during refactoring, also remove its import statement — don't leave dead imports behind. Stale imports can cause Next.js chunk/module-factory errors even when the symbol isn't referenced in JSX, especially with lazy-loaded icon libraries like lucide-react. Confidence: 0.80
- Never render `<link rel="stylesheet">` or similar head/resource tags inside client components in Next.js 16 + React 19 — client-rendered `<link>` tags go through React DOM's `useInsertionEffect` path and crash under Turbopack with "Cannot read properties of null (reading 'useInsertionEffect')". Render font/resource links in the server layout instead (with `precedence="default"`), where Next.js handles them natively. Confidence: 0.75
- When removing a feature during refactoring, also clean up the associated `useState` declarations AND all their setter calls — not just the JSX that rendered them. Dead state variables don't cause build errors (unlike dead imports) but silently bloat the component and cause confusion. This extends the "remove unused imports" discipline to React state management. Confidence: 0.70
