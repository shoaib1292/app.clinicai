- When a `npm install` fix appears to work but the user later reports the same "module not recognized" error, immediately escalate to environment-level diagnosis: check `NODE_ENV` (`$env:NODE_ENV`), `npm config get production`, and `npm config list`. A globally-set `NODE_ENV=production` causes npm to silently skip all `devDependencies`, so `npm install` succeeds for `dependencies` but leaves `devDependencies` (like `concurrently`) uninstalled. The fix is `$env:NODE_ENV='development'; npm install` — or permanently removing `NODE_ENV` from system environment variables. Confidence: 0.75

- When `prisma migrate deploy` fails in an automated script and falls back to `prisma db push`, always include `--accept-data-loss` — without it, `db push` hangs waiting for interactive confirmation on destructive changes (dropped columns/tables), which breaks unattended startup scripts like `dev.ps1`. Confidence: 0.85
