# pricing
- Pricing model: Free for clinics/hospitals; PKR 50 flat fee per appointment charged to patients — the user clarified this PKR 50 fee is for OFFLINE appointments (telemedicine has its own separate per-minute fee, see below). This PKR 50 patient fee must also serve as the target all-in internal cost ceiling — total per-consultation spend on third-party APIs (video, LLM, STT, etc.) combined should fit within PKR 50. Confidence: 0.80
- Telemedicine video consults are priced per-minute at ~1 PKR per call-minute (0.50 PKR per participant per minute), as a separate fee on top of the doctor's fee — the user explicitly decided this split (PKR 50 flat = offline only). The user worries that piling the platform fee onto the doctor's fee (e.g., 1,000 doctor + 80 telemedicine for a 30-min call) would discourage doctors from offering telemedicine, so pricing must never become an adoption barrier. Confidence: 0.8
- Show the patient a transparent fee breakdown at booking — the doctor's fee and the telemedicine platform fee as separate line items (e.g., "Doctor fee 1,000 + Telemedicine fee 80 (30 min)"), not one lumped price. The user explicitly wants both components displayed to the patient ("1,000 doctor fee aur 80 telemedicine appointment fee"). Confidence: 0.6
- Prefers multi-account free-tier key rotation as a cost-minimization strategy for third-party APIs — the same pattern used for LLM keys and AssemblyAI should be applicable to any API service (e.g., Daily.co). Manage multiple accounts and rotate through them to stay within free limits rather than upgrading to paid tiers. Confidence: 0.75
- When using free-tier API accounts with rotation, cap usage at ~90% of the free limit (e.g., 9,000 of 10,000 minutes) rather than fully exhausting it, so that ongoing/in-progress sessions are never disrupted by hitting the ceiling mid-session. The buffer should account for the worst-case duration of a single in-progress session. Confidence: 0.80
- Only Platform Admin can set/override pricing rules (markupMin, markupMax, markupDefault); Clinic Admins should NOT have self-serve markup controls. Confidence: 0.75
- Telemedicine billing is implemented as a debit to the clinic's existing PKR credit wallet (CreditLedger entry, reason `telemedicine_fee`) at 1 PKR/min — the patient pays the clinic directly as today, and no new patient-side payment infrastructure is built. Prefer extending the existing clinic wallet/credit system for new charges over building new payment rails. Confidence: 0.7
- Prefer self-hosted open-source infrastructure (e.g., self-hosted LiveKit replacing paid Daily.co) over per-use SaaS when ongoing usage costs are involved — consistent with keeping total per-consultation spend within the PKR 50 all-in ceiling. Confidence: 0.6
