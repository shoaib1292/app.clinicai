# whatsapp-safety
- When using unofficial WhatsApp APIs (Evolution/Baileys), implement multiple safety layers to minimize ban risk: daily message caps per clinic, hourly caps per patient, typing delay simulation, message debouncing, and serial delivery. Confidence: 0.85
- Typing delay should simulate natural human typing speed (250ms per word, up to 15s maximum) to avoid bot detection. Confidence: 0.80
- When an external API natively supports a timing parameter (e.g., Evolution's `delay` for typing presence duration), pass the timing value to the API so it manages the indicator duration, rather than only simulating it client-side. Confidence: 0.75
- Use a gradual warm-up strategy for daily message caps (e.g., 50/week 1, 100/week 2, scaling to 300-500 daily) rather than removing caps entirely, to minimize ban risk while scaling usage. Confidence: 0.85
- AI-generated WhatsApp replies should be kept as short as possible to appear more human-like and reduce bot detection risk. Confidence: 0.80
- The AI WhatsApp agent must never give acknowledgment-only replies (e.g., "2 min", "check kar rahi hoon") without actually performing the action — when a patient asks about timing, appointments, fees, or doctors, call the relevant tool and provide the actual result in the same turn. Confidence: 0.90
- Debounce rapid incoming messages (4-second window) into a single combined reply rather than responding to each individually. Confidence: 0.80
- Deliver WhatsApp messages serially per clinic (queue-based) rather than sending in parallel/bulk. Confidence: 0.75
- For production use where number banning is critical, prefer Meta Cloud API (official, zero ban risk) over Evolution API (unofficial, moderate ban risk); use Evolution API for exploratory/light use only. Confidence: 0.80
- When presenting available appointment slots on WhatsApp, show actual clock times with token numbers (e.g., "3:00 PM (Token #5)") rather than just token numbers like "3, 4, 5". Never list more than 3-4 slot options; if there are many slots, summarize the range (e.g., "2 baje se 8 baje tak slots hain. Konsa time?"). Confidence: 0.90
- When a patient picks a specific time or confirms with "G"/"han"/"ok"/"theek hai", call book_appointment immediately without asking for confirmation again. Confirm only once — do not re-ask "confirm karein?" after the patient has already agreed. Confidence: 0.90
- When book_appointment returns an alternativeSlot, present only that single alternative (with its time and token number) to the patient rather than re-listing all available slots. Confidence: 0.85
- After a successful booking, confirm with: date, time, doctor name, token number, fee amount, and a reminder to reach the clinic on time. Confidence: 0.80
